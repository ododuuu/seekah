# 0.44.2 交接：資料夾選擇器中文路徑亂碼修正

更新：2026-10-01。package 為 **0.44.2**。

## 範圍

- 起因：使用者在工作台「根目錄」按「加入資料夾」，選擇 `D:/備份` 後路徑變成 `D:/亂碼`。
- 根因（既有問題，0.37.0 起，非 0.44.x 回歸）：`src/folder-picker.ts` 以 PowerShell `[Console]::Out.Write(路徑)` 輸出選到的路徑；從 Node 以 `windowsHide` 啟動 PowerShell 時，輸出使用 OEM 字碼頁（繁體中文 Windows 是 CP950／Big5），Node 卻以 UTF-8 解碼。實測 `D:\備份` 輸出位元組為 `44 3a 5c b3 c6 a5 f7`（Big5），以 UTF-8 解碼得 `D:\�ƥ�`。任何含非 ASCII 字元的路徑都會受影響。
- 修正：PowerShell 改輸出 Base64（UTF-8 位元組），Node 端 `decodePickerOutput` 解碼，不再依賴主控台字碼頁。`pickerOutputStatement`、`decodePickerOutput` 匯出供測試。
- 本版是單點修正，升修訂版號；不改 SPEC。

## 驗證

- `test/m73.test.ts`：從 Node 以與選擇器相同方式啟動 PowerShell，輸出 `D:\備份`、`C:\Users\王偉晨\文件 與 資料`、`E:\𠮷野家\測試😀`、純 ASCII 路徑，逐字比對解碼結果；空輸出視為取消。
- 反向驗證：改回舊的直接輸出方式後，`D:\備份` 案例失敗（正是使用者遇到的路徑）；還原後通過。
- 檢查其他呼叫 PowerShell 的程式：剪貼簿已明確設定 UTF-8 輸入編碼、開啟文件以環境變數傳路徑、登入啟動不讀輸出，沒有同樣問題。
- 檢查使用者的真實索引（唯讀 `roots`）：只有 `C:\`，沒有被登錄成亂碼的根目錄。
- 完整 `npm test` 與 `node scripts/ui-smoke.mjs`（結果見 STATUS）。

## 限制與下一步

- 資料夾選擇器的實際對話框無法自動化，測試涵蓋的是輸出編碼路徑，不是對話框本身；請使用者重新啟動工作台後以 `D:\備份` 再試一次。
- 其餘限制與下一步同 [0.44.1.md](0.44.1.md)。
