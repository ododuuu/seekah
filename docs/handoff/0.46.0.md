# 0.46.0 交接：搜尋可取消、搜尋與狀態速度、監看漏事件防護

更新：2026-10-01。package 為 **0.46.0**。

## 範圍

- 行為權威：SPEC §83～§86；決策：D115～D118；驗證：`../0.46.0-VALIDATION.md`。承接 0.45.0。
- 起因：驗收後使用者要求處理「搜尋與速度的三項」與「監看偶爾漏事件」。依 D093 由四位手下平行開發（pi／pi2／pi3／pi4），逐一驗收後合併。

## 已完成

- **§83／D115 搜尋取消與 worker**：工作台 `/api/search`、`/api/search/count` 改在獨立 worker thread 執行，主程序不再被長搜尋卡住；新搜尋或關閉連線會取消舊搜尋（HTTP 499 `SEARCH_CANCELLED`）；UI 等待超過約 1 秒顯示秒數與「取消」，取消後保留上次結果與輸入。資源上限：程序最多 4 個 worker、閒置 120 秒回收、超過上限 LRU 終止、`X-LocalDocSearch-Client` 僅接受 1–64 個 ASCII 字元。代價：worker 冷啟動約 +60～80 ms；4 個 worker 的 RSS 約 +440 MB（大型合成索引、內容搜尋）。`src/workbench-search*.ts`、`test/m79.test.ts`。
- **§84／D116 無結果搜尋**：精確驗證改走 Buffer 路徑；解壓區段 LRU 快取程式與測試保留但**預設關閉**（`decompressedChunkCacheBytes` 預設 0）。原因：公平矩陣顯示快取只對「同一批 distinct 查詢重複」有效（p95 −61%，RSS +150 MiB），混合負載僅 −2.4%、rare 詞反而略慢，不值得預設佔記憶體。差分測試 650（小索引）＋30（大合成索引）0 差異。
- **§85／D117 索引狀態**：`index-status` 結果快取（寫入／變更時失效），新增輕量 `GET /api/index-progress` 供輪詢；`src/index-status-cache.ts`、`test/m81.test.ts`。真實索引唯讀實測：首次約 0.79 秒、之後 6～8 毫秒。**冷讀取本身沒有變快。**
- **§86／D118 監看**：child watcher 失敗只降級該直接子目錄，其餘保持 split；空檔名事件不再 `lstat`，改以 `watchDir` 排入有界的局部補掃（同目錄冷卻 5 秒、60 秒最多 4 次、退避 5→15→60 秒、每根狀態上限 1,024）；補掃讀取失敗不會刪索引。status 新增 `emptyFilenameEventCount`、`uncertainRescanCount`、`lastUncertainRescanAt`、`uncertainRescanStateCount`、`degradedSubdirectories`。`test/m82.test.ts`。

## 誠實說明（請勿誤讀）

- **漏事件的根因仍未證實**：隔離實驗（150／300／600 writes/s、含 `subst` 磁碟根）9/9 與一次 daemon probe 都找到目標，**未能重現遺失**。§86 是防護與可觀測性，不是已證明的根治。部署後請看 status 的新欄位，再決定下一步。
- 一般 split 拓撲目標可搜尋約 10 秒，預設排除後 1～3 秒；本輪沒有分段計時，不能把 10 秒歸因於單一階段。
- 先前報告的「index-status 約 2 秒／p95 約 4 秒」受機器負載與冷快取誇大；閒置實測約 0.75 秒。
- 瀏覽器煙霧測試「索引進行中切換背景更新仍保持 API parity」在高負載下偶發失敗（乾淨 main 也會），本次合併後全過，但仍屬時序敏感。
