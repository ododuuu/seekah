# 0.41.1 交接：局部更新重用根目錄排除規則

更新：2026-09-29。package 為 **0.41.1**。

## 範圍

- 行為權威：SPEC §61；決策：D092；驗證：`../0.41.1-VALIDATION.md`。
- 起因：效能審查（P0-4）發現 `applyFileUpdateLocked` 每處理一個檔案都重新讀取 `.localdocsearchignore` 並查詢 ignore scope，而 `LiveUpdateEngine` 的 `RootState` 已持有同一份排除規則。
- 純效能改動，排除結果與產品行為不變。依 D093 以分支 `perf/reuse-root-exclusion` 開發後審查合併。

## 已完成

- `LocalUpdateOptions` 新增可選 `exclusion`；引擎每批局部更新開始時以 `RootExclusion.loadSync` 載入一次並傳給整批。
- 規則檔載入失敗時：事件過濾照舊退回內建規則，但批次**不傳** `exclusion`，每個檔案維持原本的載入與拋錯，更新失敗、不寫入索引。
- 未傳入 `exclusion` 的呼叫者（CLI、watch 等）維持每檔載入。
- 測試：m50（4 項）。d) 經反向驗證：把 `src/live-update.ts` 換回未防護版本時失敗，修正版通過。

## 審查紀錄

- 第一版把引擎退回的內建規則傳給批次，規則檔錯誤時會索引應排除的檔案；已退回修正。
- 第一版 d) 無法分辨正確與錯誤實作（測試自行清空傳入值、等待條件恆真）；重寫後經反向驗證。
- m50 d) 為了穩定觸發批次，會刪除測試資料庫的寫入鎖檔並呼叫引擎私有方法；僅限測試程式。

## 未完成／限制
