# 0.39.1 交接：自動更新不處理被排除的路徑

更新：2026-09-28。package 為 **0.39.1**。

## 範圍

- 行為權威：SPEC §53；決策：D084；驗證：`../0.39.1-VALIDATION.md`。
- 起因：0.39.0 驗證時發現背景自動更新 12.5 小時處理 2,323 萬個 `AppData` 事件、局部更新 0，持續占用多個 CPU 核心。
- 根因與修正：
  1. 使用者排除規則沒有套用到監看與事件層 → split 模式不監看被排除的直接子目錄；事件入口以與完整掃描一致的判斷（任一上層目錄或本身被排除）丟棄，不 `lstat`、不寫佇列、不排防抖。
  2. 防抖每個事件都重設，持續事件時永遠不觸發，一般檔案與背景校正都停住 → 最長等待 10 倍防抖時間。
  3. 局部更新只比對路徑本身 → 改用同一個判斷；佇列中的被排除路徑直接 ack，不觸發子樹同步。
  4. 新目錄 attach 前消失時退回 coarse → 維持 split。
  5. `.localdocsearchignore` 變更時依新規則重建 watcher。
- status 新增「已排除事件」（`excludedEventCount`）。不改索引或工作佇列 schema。

## 未完成／限制

- 公司 Windows 人工驗收未回報，**不得宣稱 Windows 驗收通過**。
- coarse 模式下事件過多時，Windows 會送出沒有檔名的事件，只能整根校正；這仍會吃 CPU。本版讓根目錄盡量維持 split，沒有消除 coarse 的這個限制。
- 使用者目前執行中的背景自動更新仍是舊版程式，需要 `autoupdate stop` 後以新版 `autoupdate start`（注意：新版寫入程序開啟 0.38.1 格式的 index 時會觸發 0.39.0 的區段儲存遷移）。
