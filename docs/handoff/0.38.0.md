# 0.38.0 交接：block 級 FTS5 位置索引搜尋後端

更新：2026-09-27。package 為 **0.38.0**；0.37.0 各階段從未單獨發布，全部併入本版。

## 範圍

- 行為權威：SPEC §50；決策：D081；研究與 prototype：`../research/search-architecture-2026-09-27/`（`PROTOTYPE-RESULTS.md`）。
- 搜尋改用 block 級 FTS5 索引：
  - content：trigram `detail=full` 的 phrase（`case_sensitive 1`），以及 `detail=none` 的 unigram／bigram token。
  - 檔名與 heading 各自有小型 trigram／unigram／bigram 表。
  - 排序前不讀正文；payload 只為當頁 snippet 與 passages 讀取。
- 搜尋語意不變：rank、代表 block、all-terms 覆蓋度、`field`／`sort`／type／root／subtree／status／結果內搜尋、snippet、stable reference 都相同。
- 舊 index 由 writer（`index`、Workbench 背景升級、sync）以 `block_index_1` marker 逐批遷移，可中斷接續。完成時刪除 `document_blooms`、`document_payload_blooms`、`search_unigrams`、`search_trigrams`；fresh index 從不建立這些表。遷移完成前，唯讀 CLI／MCP 使用舊路徑，結果相同但較慢。
- 修正既有 bug：含 U+0000 且 ≥3 字的查詢不再丟出 FTS5 `unterminated string`。
- search trace schema 4：
  - 新增 `block-index` source 與 `block-index`／`block-index+restricted-ids` strategy。
  - 新增 counts `indexPostingRows`、`indexCandidateBlocks`、`indexVerifiedBlocks`。
- heading snippet 直接讀 `blocks.heading`，不再解壓 payload。

## 未完成／限制

- 公司 Windows 人工驗收未回報；本版證據只來自本機 win32，**不得宣稱 Windows 驗收通過**。
- 索引大小約為舊版的 2.4 倍（真實 235,463 文件：1.37 GiB → 約 3.3 GiB）；DB 不做 VACUUM。
- 舊 index 一次性遷移在本機真實 store 約需 35 分鐘（可中斷接續）；不含 parser 的單份文件寫入時間約為舊版的 1.6–1.8 倍。
- 常見單字（例如 `e`，15.6 萬筆結果）約 6–11 s，與 0.37 大致持平；同一程序重複查詢時 SQLite GROUP BY 會變慢，原因未查明。
- 命中十萬筆以上的查詢（例如單字 `e`）仍需數秒，瓶頸在結果集大小；total count／top-K 待另行決策。
- 巨大 block（跨上百個 payload）的當頁 snippet 仍需讀完整 block。
