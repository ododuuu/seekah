# 0.41.0 交接：工作台背景自動更新管理、遷移 SQLITE_BUSY 重試、背景校正拆分失敗類型

更新：2026-09-29。package 為 **0.41.0**。

## 範圍

- 行為權威：SPEC §58、§59、§60；決策：D089、D090、D091；流程：D093；驗證：`../0.41.0-VALIDATION.md`。
- 本版首次以平行分支開發（D093）：三條功能分支各自實作、審查，再依規格章節順序合併。
  - `feat/autoupdate-gui`：§58／D089。
  - `feat/sqlite-busy-retry`：§59／D090。
  - `feat/failed-scope-split`：§60／D091。

## 已完成

- §58 工作台設定頁：
  - 「登入 Windows 時自動啟動背景自動更新」勾選框，重用 `autoupdateStartupEnable`／`Disable`／`Status`；非 Windows 停用並說明。
  - 背景自動更新健康摘要：狀態、待處理／佇列、累計事件／局部更新／已排除事件、同步時間、最近錯誤、目前參數；只在控制通道實際回傳 `LiveStatus` 時顯示；手動「重新整理」，不輪詢。
  - 可調變更等待（0.2～60 秒）與完整校正間隔（0.25～24 小時），存於索引 metadata；工作台啟動 daemon 時套用；執行中變更時停止再啟動；已註冊的登入捷徑一併更新參數。CLI 預設與旗標不變。
  - §46 三處「GUI 不做 autoupdate」條文加註 0.41.0 更新。
- §59 遷移交易遇到 SQLITE_BUSY（errcode 5／6）時有限重試：立即一次，再依 100、300、1000、2000、5000 ms 重試；尊重 AbortSignal；最終失敗仍由 CLI 顯示 INDEX_BUSY。
- §60 背景校正：`readFailures`（列舉或 IO／權限錯誤）與 `deferredChecks`（檔案不穩定、待辦阻擋、尚未完成）分開記錄與顯示；兩者都使 `complete = false` 並阻止刪除核對。沿用 `failed_scopes_json` 欄位，舊陣列保守解讀為讀取失敗，損壞資料標為根目錄延後核對。
- 測試：m47（4 項）、m48（1 項，經反向驗證）、m49（4 項）；m37-reconcile 斷言改用新欄位。
- SPEC §58～§60、D089～D091、D093、AGENTS.md、STATUS、USER-GUIDE、NEXT-TODO、handoff、驗證文件。
- 本批已檢視並更新使用手冊：設定頁（登入啟動、健康摘要、可調參數）、`autoupdate status` 的讀取失敗／延後核對解讀、常見問題。
