# 0.39.4 交接：新資料夾分批展開

更新：2026-09-28。package 為 **0.39.4**。

## 範圍

- 行為權威：SPEC §56；決策：D087；驗證：`../0.39.4-VALIDATION.md`。
- 起因：使用者要求繼續處理尚未改善的項目；0.39.3 後只有新建、移入或改名的資料夾會觸發子樹掃描，但仍一次同步整棵（列出、解析、寫入、刪除核對同一輪，持有 writer lock）。
- 修正：
  1. 資料夾待辦逐步展開：每輪最多讀 2,000 個目錄項目（讀到一半的清單保留到下一輪），檔案寫入工作佇列，走 §54／§55 的分批處理。
  2. 展開出來的待辦（佇列 `reason = expand`）排在同一圈的事件待辦之後；收到事件即升為事件待辦，已是事件者不降級。
  3. 展開完成且無讀取失敗時，對未看到的舊文件確認不存在後排入刪除。
  4. 超過佇列上限時沿用 dirty scope → 背景校正。
- 不改 schema。展開狀態只在記憶體，重啟後重新展開。
