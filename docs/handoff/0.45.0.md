## 已完成

- **§78／D110 結果可選取、可複製**：檔名、路徑、片段、臨時文件名稱、上下文名稱可框選；點檔名開啟原檔保留，剛選取文字時不觸發開啟；每筆結果「複製路徑」「複製檔名」，剪貼簿失敗有後備；無 `innerHTML`。`src/workbench-app.ts`。
- **§79／D111 Toggle Switch 與「關不掉」**：設定頁四個布林控制改為 `role="switch"` 按鈕；根因是儲存後等待約 2 秒的 `refreshStatus()`，慢速舊回應蓋回舊狀態；現在 POST 回應是狀態來源，`statusRevision` 保護過期回應，失敗回復並顯示明確錯誤。API 層本來就正常。
- **§80／D112 全部詞多段落後端**：`mode=all-terms` 當頁每筆帶 `passages`／`omittedTerms`；不改結果集合、排序、`total`；差分測試 0 差異。`src/search.ts`、`src/mcp-tools.ts`、`src/workbench.ts`、`src/cli.ts`（CLI all-terms 輸出各詞段落）。
- **§82／D114 多段落畫面**：列表與表格顯示各段（位置標籤、命中詞、高亮片段），單段維持原外觀。
- **§81／D113 開機補捉與開啟提醒**：兩個三態設定。`startupCatchupMode`（背景更新啟動時處理停止期間變更：預設 `auto`，可 `ask`／`off`，CLI 可用 `--startup-catchup`）；`workbenchOpenMode`（開啟工作台時背景更新沒在執行：**預設 `ask`**，顯示提醒列四個動作；`auto` 自動啟動；`off` 不處理）。**沒有明確選 `auto` 不得自動啟動任何程序**，伺服器端再次確認。`src/startup-catchup.ts`、`src/workbench-open.ts`、`src/autoupdate*.ts`、`src/live-update.ts`、`src/store.ts`。

## 審查紀錄與教訓

- **§81 第一版沒涵蓋使用者的原始情境**：手下做的是「背景更新程序已在跑時的 gap 策略」，使用者的情境是「打開時背景更新根本沒在跑」。驗收時對照使用者原話發現，退回補上 `workbenchOpenMode` 與提醒列。**教訓：驗收要對照使用者的原話與情境，不只看測試通過。**
- **§81 預設值**：第一版舊索引預設 `auto`，與「不得在使用者未選 auto 時自動啟動任何程序」衝突的風險；`startupCatchupMode` 預設 `auto` 是維持既有 daemon 行為（不變），`workbenchOpenMode` 預設 `ask`。
- **§80 多段落後端**：另一位手下以差分腳本獨立驗收（650＋30 組 0 差異），並實測長文件代價（一頁約 20 → 40 ms）。
- **每次合併都在合併後的狀態重跑完整測試與煙霧測試**：§78 與 §79 各自通過，合併後 `scripts/ui-smoke.mjs` 與工作台前端有衝突，需「兩邊都保留」手動合併；合併後的驗證證明沒有互相影響。
- 手下在 PowerShell 指令字串裡嵌入雙引號會讓指令截斷（一次派工因此失敗，已重送）；派工字串請避免內嵌雙引號。
- Grok（xAI）額度用完，後續只用 GPT 手下。
- 整合時 `docs/SPEC.md`、`docs/DECISIONS.md` 各分支都在檔尾追加而衝突；解衝突用「兩邊都留、依編號排序」，並檢查重複區塊；`D022` 重複是既有問題。

## 使用者要做的事（部署）

1. 本機 `main` 領先 GitHub，工作階段讀不到 GitHub 憑證，請在自己的 PowerShell 執行：`git -C C:\Users\mains\seekah push origin main`；推送後用 `git ls-remote origin refs/heads/main` 確認。
2. 公司電腦：`git pull origin main`、`npm ci`、`npm run build`（**舊的編譯結果不會自動更新**，`seekah-ui.cmd` 看到 `dist` 存在就直接用）；關掉舊的工作台視窗，重新雙擊 `seekah-ui.cmd`。
3. 啟動背景更新（本機目前是停止狀態，0.44.0 部署時被停止）：設定頁打開「背景自動更新」，或 `.\seekah.cmd autoupdate start`。
4. 打開工作台若背景更新沒在跑，會看到提醒列；想全自動可到設定把「工作台開啟提醒策略」改為「自動」。
