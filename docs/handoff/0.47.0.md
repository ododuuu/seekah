## 已完成

### §87／D119：工作台主題切換

- 頂列原生按鈕循環「自動／淺色／深色」，自動沿用 `prefers-color-scheme`。
- 顯式主題只以 `theme=light|dark` 保存於目前工作台 URL query；自動模式移除 query，token fragment 原樣保留。
- 不使用 `localStorage`、`sessionStorage`、cookie、IndexedDB、設定 API 或外部服務；查詢、路徑、文件內容、Key 與答案不進 URL。
- `m83` 涵蓋三態、白名單、套用、重新載入、fragment 與反向契約；ui-smoke 涵蓋三種桌面寬度的循環與 reload。

### §88／D120：結果片段與多段落選擇

- phrase／單詞同一文件最多展示兩個不同命中區段；第一片段的 rank、主要 snippet、heading、location、排序與 stable 欄位保留。
- 檔名與內文共命中時追加實際 body passage；`field=filename` 不讀取或虛構 body。
- all-terms 各詞選擇與其他詞距離最近的 ordinal；距離相同選小 ordinal，沿用相鄰合併與原始文字詞序。
- 列表位置欄最多 24%，表格最多 28%，保留 72／60 px 最小寬度。
- `m84` 與既有搜尋／UI 回歸保護第二片段、filename/content 邊界、最近詞及窄欄；搜尋差分核心投影 0 差異。

### §89／D121：監看分階段計時與穩定等待重疊

- `lastTiming` 記錄 event→schedule、stable wait、enumerate、lock、commit；`autoupdate status` 可顯示最近批次各階段。
- 每檔仍完成第二次 identity 檢查；後續檔案可在前一檔解析／準備／提交時並行穩定等待，不持有 writer lock。
- 隔離合成安靜案例寫入至可搜尋約 3.0 秒降至 1.5 秒。
- 這是合成案例改善，不是一般固定 SLA；監看漏事件根因仍未證實，沒有宣稱已解決。

### §91／D123：背景寫入期間搜尋慢化

- 160 文件、每份 8 blocks、4 readers／1 writer 的隔離負載中，產品現況相對 idle 約 p50 1.07x、p95 1.05x。
- 未重現既有 1.3～1.6 倍慢化；mmap／autocheckpoint 對照沒有穩定收益，維持既有 WAL、checkpoint 與唯讀連線設定。
- `m87` 只保護背景提交時的 data version、完整結果與 revision 可見性；若使用者環境仍重現，下一案先加分段 timing，不把本次未重現寫成已修正。

### §92／D124：長文件多段落候選讀取

- current chunk store 使用 chunk／heading FTS 作保守候選，exact block matching 仍在搜尋層執行；legacy／block-index 維持完整 fallback。
- 合成長文件當頁 p50 約 93 ms 降至 58 ms；結果集合、順序、rank、代表位置、snippet、passages、total 與 `totalRelation` 不變。
- 查詢詞分散於幾乎所有 chunks 時收益可接近零；此量測不代表所有真實文件固定加速。
- `m88` 逐欄比對完整與候選讀取，並確認驗證 chunks／bytes 減少。

- 公司電腦：取得 0.47.0 版本後執行 `npm ci`、`npm run build`，關閉舊工作台並重新啟動 `seekah-ui.cmd`；背景更新需重新啟動才會載入 §89 的 status timing 與等待排程。
