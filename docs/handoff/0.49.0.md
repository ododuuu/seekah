# 0.49.0 交接：錯誤邊界、監看診斷與狀態 JSON

更新：2026-10-02。package 版本：`0.49.0`。

## 範圍

本版行為依 SPEC §§101–108、D137–D144；測試檔最高編號為 `m104.test.ts`。§90／D122 是歷史保留空號，本版沿用，不重排編號。

- `fix/robust-errors-49`：§§101–102、D137–D138、`m97`–`m98`。`compact` 的 SQLite busy／locked 固定分類為 `INDEX_BUSY`；`rememberError` 分類 busy／recovery；`cleanupOrphanRoots` 失敗時降級啟動並於下次重試；pi3 補強測試。
- `fix/status-mcp-49`：§§103–105、D139–D141、`m99`–`m101`。工作台顯示索引容量與 SQLite sidecar；stdio MCP `explain_path` 維持 tokenless 且只回查詢 root；8.3 短名與 `subst` 正規化；DECISIONS 由新到舊排列。
- `research/watch-miss-49`：§§106–107、D142–D143、`m102`–`m103`。14 個 fs.watch 合成壓力情境核對 626 份 synthetic token，遺失 0，未重現漏事件；新增匿名 `autoupdate diagnose`，根目錄以 `R1`／`R2` 序號及相對深度表示，不輸出路徑或雜湊；某輪觀察到 stable wait 約 16 秒。
- `feat/status-json-49`：§108、D144、`m104`。`status --json` 與 `autoupdate status --json` 提供含 `schemaVersion: 1` 的結構化契約。

本次 release commit 只更新 `package.json`、`package-lock.json` 與文件，不修改 `src/`、`test/`；既有 LocalDocSearch 資料目錄、`LOCALDOCSEARCH_DATA_DIR`、IPC／MCP／`docsearch` 相容入口維持不變。

## 已完成

- SQLite busy／recovery 錯誤在 CLI、live status 與 background engine 邊界使用固定對外分類，不把 SQLite 原文當成使用者契約。
- 工作台容量資料沿用既有 storage footprint，包含主庫與已知 WAL／SHM／journal／writer／live／work sidecar；MCP `explain_path` 不擴張成 root list 或任意讀檔。
- diagnose 只查詢 live daemon；當前輸出使用本次 snapshot 的 `R1`、`R2`……與相對深度，不輸出完整路徑、檔名、內容或雜湊。
- JSON status 輸出固定 `schemaVersion: 1`；不指定 `--json` 時的人類輸出維持原契約。
- `docs/USER-GUIDE.md` 已檢視；其中已有 status JSON、autoupdate diagnose、R 序號與隱私邊界說明，本版不另建立版本化使用教學。

## 誠實限制

- 626 份 synthetic token 的遺失 0 只表示該輪沒有重現漏事件；fs.watch 根因仍未證實。某輪 stable wait 約 16 秒，會受負載影響，不能當固定 SLA。
- 使用者若要提供實際觀察，需先重啟背景更新，再執行 `seekah autoupdate diagnose` 回傳匿名摘要與 timing。diagnose 不會自行啟停 daemon。
- `autoupdate.log` 仍記錄完整路徑；它是本機檔案，不等於 diagnose 的匿名輸出，不能將 log 外傳。
- 本版沒有公司 Windows 使用者驗收回報，不能宣稱 0.49.0 已通過公司 Windows。

## 部署與下一步

1. 執行 `npm ci`、`npm run build`，沿用既有 LocalDocSearch 資料目錄，不刪除或搬移索引。
2. 腳本改用 `status --json`／`autoupdate status --json`，先檢查 `schemaVersion` 並忽略未知新增欄位。
3. 若懷疑監看漏事件，重啟背景更新後執行 `seekah autoupdate diagnose`，回傳匿名輸出與 timing；完整 `autoupdate.log` 留在本機。
4. JSON 欄位若需刪除、改名、改型別或改語意，必須先更新 SPEC／DECISIONS 並升級契約。
