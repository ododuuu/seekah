# 0.38.1 交接：大量刪除效能與遷移記號清理

更新：2026-09-28。package 為 **0.38.1**。

## 範圍

- 行為權威：SPEC §51；決策：D082；驗證：`../0.38.1-VALIDATION.md`。
- 起因：使用者在真實 index 以 `.localdocsearchignore` 排除 `AppData` 後，刪除校正要移除 175,324 份文件，0.38.0 單一交易跑了約兩小時。
- 三項修正：
  1. 外鍵子表必須有索引：新增 `index_migration_documents(document_id)` 索引（writer 開啟時補上），並以測試檢查全部外鍵。
  2. 遷移 marker 只在遷移期間存在：遷移完成時清除；0.38.0 殘留的 marker 由 writer 開啟時清除；完成後的寫入不再寫 marker。
  3. `removeMissing` 每 1,000 份一個交易，批內以 temp table 集合式刪除；批次之間可取消、回報「刪除校正」進度，已提交的批次保留。
- 搜尋語意與結果不變。

## 已完成

- SPEC §51、D082、STATUS、USER-GUIDE（常見問題新增一列）、README、ROADMAP、NEXT-TODO、handoff 更新。
- `src/store.ts`：
  - schema：`index_migration_documents_document` 索引。
  - `purgeCompletedMigrationMarkers()`：writer 開啟既有 index 時清除已完成遷移的 marker。
  - `migrateBlockIndex`／`migratePayloads` 完成時刪除自己的 marker；`writeBlockIndexRows` 只在遷移期間寫 marker。
  - `formatStatus().blockIndexCompletedDocuments`：完成時等於文件總數。
  - `removeMissing` 改為 async、分批，新增 `removeDocumentBatch()`。
- `src/sync.ts`：傳入 signal／onProgress；取消時把已提交的刪除份數放進 partial report。`reconcile.ts`、`local-update.ts` 改為 `await`。
- 測試：新增 `test/m41.test.ts`；m24、m38、m40 調整 marker 預期與 `await`。
- 真實 store 複本刪除 benchmark：見驗證文件。
