## 各項修正的證據

### §68／D100 公平輪替（`test/m61.test.ts`）

- 根因由插樁證實：事件雜訊夾具（140 個頂層資料夾、coarse 單 watcher、真實 `fs.watch`）下 `runRoot` 4 次決策全是 `batchReconcile`，`localUpdateCount` 維持 0；`schedule_set` 16,414 次、`schedule_clear` 16,410 次、實際觸發 3 次。每輪間隔約 16 秒，遠大於 5 秒的 `reconcileDue`。
- 反向驗證（監工獨立執行）：把 `forceLocal` 改成 `false` 後，「校正批次後下一輪必須進入 local branch」失敗；還原後通過。
- 中等雜訊（約 300 writes/s、Desktop 目標檔）對照：main 3 次皆 `>60,000 ms` 搜不到；修正版第一組 3 次中 1 次 3,241 ms 搜到，第二組診斷重跑 3 次中 2 次約 3.3 秒搜到。無雜訊對照 main 2,940 ms、修正版 2,957 ms，沒有退化。
- 剩下的失敗不是排程：失敗那次 `handleEvent` 收到 22,655 個事件，目標檔名事件為 0、空檔名 168 個，目標從未進 work queue（見「未解決」）。
