## soak 與 -wal 成長

產品 `checkpointWal()`。窄查詢 10 分鐘：`-wal` 取樣均約 **1.0 MiB**；reader p95 約 19.5／19.9 ms。寬查詢 10 分鐘最大 **85.8 MiB**，正常 close 後仍 **28.1 MiB**。寬 20 分鐘最大 **207.4 MiB**，close 後 **11.5 MiB**。RESTART／TRUNCATE 在寬 snapshot 下大量 busy（20 分鐘各 3138 busy／23 success）。

正常 close 後 `-wal` 仍可能殘留。**推測**最後關閉者為唯讀連線、未做可寫 checkpoint；後續可寫重開可清除。未確認所有關閉順序。

寬 20 分鐘（1 寫入者＋2 讀取者）三程序 RSS 約 278→360 MiB、HandleCount 675→724，未收斂。

**記憶體／handle 對照（只有讀取者、無寫入者、寬查詢、20 分鐘、2 個 reader 程序）：** main 舊版 rollback 每個 reader RSS 約 102→148／102→140 MiB、HandleCount 固定 220；WAL 版 93→136／93→131 MiB、HandleCount 固定 224；WAL 加每次搜尋後手動 GC 89→132／100→135 MiB、HandleCount 固定 224；三組搜尋失敗皆 0。結論：RSS 緩升在 main 舊版同樣出現，WAL 版沒有更糟（峰值略低）；讀取者 handle 沒有累積。強制 GC 讓 JS heap 與 ArrayBuffer 平穩（heapUsed 約 13.8 MiB）但 RSS 仍緩升，**推測**來自 SQLite 原生快取與記憶體映射（唯讀連線設 `cache_size` 64 MiB、`mmap_size` 1 GiB），不是 JavaScript 物件洩漏；本機沒有 Sysinternals Handle 可分類 handle 類型，故無法證實。先前含寫入者的 soak 出現的 handle 增加（675→724）在只有讀取者的對照未重現，來源（寫入者或 checkpoint 嘗試）**未查明**。
