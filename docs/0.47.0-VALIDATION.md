## 三條分支的交付內容

### §87～§88／D119～D120：工作台與搜尋結果

- 工作台提供自動／淺色／深色主題按鈕。
- 顯式主題寫入目前工作台 URL 的 `theme=light|dark` query；自動模式移除 query，token fragment 保留；不使用 Web Storage、cookie、IndexedDB 或設定 API。
- phrase／單詞結果可顯示同一文件第二個命中片段。
- 檔名與內文共命中時顯示實際 body passage；`field=filename` 不讀取內文。
- all-terms 各詞選取與其他詞最近的命中區段；位置欄縮窄。
- rank、sort、total、分頁、`filenameOnly` 與其他穩定核心結果欄位不變。
- `test/m83.test.ts`、`test/m84.test.ts` 與既有回歸包含在上述完整測試中；反向契約涵蓋主題狀態、fragment、第二片段、檔名欄位邊界、最近詞及欄寬。

### §89／D121：監看分階段計時與穩定等待重疊

- `lastTiming` 提供 event→schedule、stable wait、enumerate、lock、commit 分階段資訊。
- 後續檔案可在前一檔解析／準備／提交時進行穩定 metadata 觀察；仍保留第二次 identity 檢查、批次上限、queue 與 at-least-once 語意。
- 隔離合成安靜案例的寫入至可搜尋時間約由 3.0 秒降至 1.5 秒。
- 這只證明該合成案例的排程成本改善；監看漏事件的底層根因仍未證實，不能宣稱已根治。

### §91／D123：背景寫入期間搜尋慢化

- 160 份文件、每份 8 blocks、4 readers 與 1 writer 的隔離合成負載中，產品現況相對 idle 約 p50 1.07x、p95 1.05x。
- 未重現既有 1.3～1.6 倍慢化；停用 readonly mmap 或調整 autocheckpoint 沒有穩定改善，未修改 WAL、autocheckpoint、checkpoint 或唯讀連線設定。
- `m87` 保護背景提交期間的資料版本可見性與完整結果，不把毫秒門檻寫成產品契約。
- 若使用者環境仍重現，下一步應分段量測 event、transaction、checkpoint、候選驗證與 page materialization；本版不宣稱問題已解決。

### §92／D124：長文件多段落候選讀取

- current chunk store 的當頁多段落讀取使用既有 chunk／heading FTS 作保守候選，再由搜尋層 exact verify。
- 合成長文件量測的 p50 約由 93 ms 降至 58 ms；結果選擇、片段語意、排序與舊索引 fallback 不變。
- 查詢詞若分散於幾乎所有 chunks，或使用 legacy／尚未完成 migration 的索引，收益可能接近零。
- `m88` 逐欄比對完整讀取與候選讀取，並驗證候選路徑的 chunks／bytes 較少。
