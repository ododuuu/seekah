  - 還原：heading-only 段落、`section`／`page` 位置、跨區段的超大段落，還原後與原輸入完全相同；每段 snippet 正確。

  - 結果內搜尋：延遲過濾層與舊的 restricted ids 完整清單一致（排序、rank、代表段落）；精確模式的總數正確。
  - 遷移：0.38 block index 與 0.38 以前兩種形狀的 index 都能遷移；唯讀開啟不遷移；第一批後取消可接續；遷移前後結果一致；完成後舊表、markers、舊版 metadata 全部移除，重開不會重建。

- `test/m40.test.ts` 改為區段引擎對逐文件 `rankDocument()` 的差分：140 個查詢 × 7 種組合（phrase／all-terms、`field`、`sort`、type／root／status、subtree、restricted ids），完整結果與第 1 頁 snippet 全部相同。

- **大小**：遷移並自動壓縮後 **139,251,712 bytes（132.8 MiB）**，約文字量的 0.77 倍。
- **正確性**：73 個查詢（13 個指定＋60 個隨機子字串）的完整結果清單（路徑、rank、代表段落、heading、location、來源），雜湊在遷移前（0.38.1）與遷移後（0.39.0）**全部相同**，共 224,224 筆結果。

## 未驗證／限制

- 公司 Windows 人工驗收未回報。
- 稀有詞的第一頁比 0.38 慢（數十毫秒 → 150–300 ms）：不記位置的索引必須解壓候選區段確認命中。
- 快速模式要驗證到 500 份才回應（研究原型量的是找到 20 份），所以常見詞第一頁為 0.3–1.2 s。
- 單字元等高頻詞的準備工作（查檔名候選、載入數萬份候選文件並排序）約 0.4 s，與內文驗證無關。
- 量測期間發現既有問題：背景自動更新會處理被排除資料夾（例如 `AppData`）的全部檔案事件，12.5 小時累計 2,323 萬個事件、局部更新 0，持續占用多個 CPU 核心。已列入 NEXT-TODO，本版未處理。
