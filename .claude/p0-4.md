## P0-4：重用 `RootExclusion`，不要每檔重讀規則

- **程式證據：** `src/live-update.ts:99-108` 的 `RootState` 已保存 `exclusion`；`src/live-update.ts:257-272` 在建立 state 時載入它。但 `src/local-update.ts:92-99` 的 `loadRootIgnore()` 每次都呼叫 `RootExclusion.load()`，而 `src/local-update.ts:182-186` 每一個 `applyFileUpdateLocked()` 又呼叫一次。`src/root-exclusion.ts:27-36` 會重新讀 root／合併 scope 的 ignore files，並查 `store.ignoreBases(root)`。
- **問題機制：** 一批 500 個檔案會重複非同步 read `.localdocsearchignore`、解析 regex、查 scope metadata；這些工作在目前 local writer lock 內發生。移入 600 檔或背景 reconcile 時，規則本身通常沒有變，卻被重複建立。
- **建議做法：** 讓 `LocalUpdateOptions` 可接收目前 root 的 immutable `RootExclusion`，`LiveUpdateEngine` 直接傳 `state.exclusion`；root／ignore file 事件已在 `src/live-update.ts:1063-1071` 重新載入與排定校正，該處同步替換傳入快取。一般直接呼叫 local-update 的路徑仍可 fallback 到 `loadRootIgnore()`。
- **預期效益：** 減少每檔 ignore read、regex 建構與 scope SQL；大量局部更新的批次前置時間、lock-held time 與 CPU 下降，且不改排除語意。
- **風險：** 快取失效若漏掉 ignore scope merge、規則檔 rename 或根目錄變更，會索引被排除內容；必須以事件重載、root refresh 與測試注入保證生命週期。
- **量測驗證：** 記錄每批 `loadIgnoreRules` 次數、`ignoreBases` SQL 次數、規則解析時間、local batch lock-held time；在 600 檔移入、ignore 變更前後各跑一次，確認新規則立即生效、取消排除後檔案可回到索引，並比較結果 hash。
